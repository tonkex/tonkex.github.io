    학습과 추론은 무엇이 다를까?¶

    모델에 질문을 보낼 때마다 다시 학습시키는 걸까요? 그렇지 않습니다. 학습(training)은 데이터를 이용해 모델의 가중치를 바꾸는 과정이고, 추론(inference)은 학습된 가중치를 사용해 새 입력의 출력을 계산하는 과정입니다. 이 차이를 알면 모델을 직접 만들지, 기존 모델을 조정할지, 서빙 비용을 어떻게 볼지 판단하기 쉬워집니다.

    이 장은 Modular의 Training vs. inference를 번역·재구성했습니다. 기준 원고는 커밋 07e93d6입니다. 별도의 정확성 보완은 한국어판 보충 설명으로 표시합니다.

    모델의 생애주기 살펴보기

    실제 운영에서 발견한 문제는 새 데이터·평가·학습 단계로 돌아가 다음 모델 버전에 반영할 수 있습니다.

    학습: 모델의 가중치를 바꾸는 과정¶

    모델은 처음부터 문장을 잘 완성하지 못합니다. 학습에서는 많은 예시를 보여 주고, 예측과 목표 사이의 차이인 손실(loss)을 계산한 뒤, 그 차이가 줄어들도록 가중치를 조정합니다. 한 번의 학습 반복을 단순화하면 입력 → 예측 → 손실 계산 → 역전파 → 가중치 갱신입니다. 역전파는 어느 가중치를 어느 방향으로 바꿔야 손실이 줄어드는지 계산하는 단계입니다.

    원문이 소개하는 대표적인 학습 방식은 다음과 같습니다.

    • 자기지도 학습(self-supervised learning): 별도의 정답 라벨을 사람이 달지 않아도 데이터 일부를 예측하도록 학습합니다. 언어 모델의 다음 토큰 예측이 대표적인 예입니다.
    • 지도 학습(supervised learning): 입력과 원하는 출력이 짝지어진 예시로 학습합니다. 특정 지시를 잘 따르도록 조정할 때 사용할 수 있습니다.
    • 강화 학습(reinforcement learning): 행동이나 출력에 대한 보상·피드백을 이용해 목표에 맞게 개선합니다. LLM에서는 선호도나 검증 가능한 결과를 보상으로 쓰는 방법이 있습니다.

    대규모 사전 학습은 많은 계산과 여러 가속기를 요구할 수 있습니다. 완성된 모델에 특정 작업의 데이터를 더 학습시키는 파인튜닝(fine-tuning)도 학습의 한 형태입니다. 학습을 마친 뒤에도 새로운 데이터와 평가 결과에 따라 다른 버전을 다시 만들 수 있습니다.

    한국어판 보충 설명: ‘한 번 드는 비용’의 의미

    원문은 학습을 추론에 비해 초기의 큰 비용으로 설명합니다. 이는 특정 모델 버전을 만드는 시점의 비용 구조를 비교한 것입니다. 제품이 계속 개선된다면 데이터 수집, 평가, 재학습, 파인튜닝 비용도 반복됩니다. 학습 비용을 언제나 정확히 한 번만 발생하는 비용으로 계산하지 마세요.

    추론: 학습된 모델을 새 입력에 사용하기¶

    추론에서는 저장된 가중치를 불러와 새로운 질문이나 문서에 적용합니다. 예를 들어 고객이 질문을 보내면 모델은 입력을 토큰으로 바꾸고, 학습된 가중치로 다음 토큰을 계산해 답을 만듭니다. 일반적인 추론 요청은 가중치를 바꾸지 않습니다. 사용자의 질문을 한 번 보냈다고 모델 자체가 그 사실을 영구적으로 학습하는 것은 아닙니다.

    모델 하나를 만드는 학습 작업은 길고 무거울 수 있지만, 추론은 서비스가 운영되는 동안 요청마다 반복됩니다. 요청 수, 입력 길이, 출력 길이가 늘면 GPU 계산·메모리·네트워크 사용과 비용도 누적됩니다. 그래서 TTFT와 처리량, GPU 메모리, 배칭을 따로 다룹니다.

    한국어판 보충 설명: 추론이 항상 실시간은 아닙니다

    원문은 사용자에게 곧바로 응답하는 실시간 추론을 중심으로 설명합니다. 하지만 밤새 문서 수천 개를 분류하거나 요약하는 오프라인 배치 추론도 추론입니다. 가중치를 업데이트하지 않고 새 입력에서 출력을 계산한다는 정의가 핵심입니다. 실시간 서비스는 개별 지연에, 오프라인 작업은 총 처리량·완료 시간·비용에 더 무게를 둘 수 있습니다.

    같은 모델의 두 단계, 무엇을 비교해야 할까?¶

    비교할 질문 학습 추론
    목적은? 데이터로 모델의 예측 능력을 만든다. 이미 만든 모델을 새 입력에 사용한다.
    가중치를 바꾸는가? 예. 손실과 피드백에 따라 갱신한다. 일반적인 서빙 요청에서는 바꾸지 않는다.
    입력은? 많은 학습 예시와 평가용 데이터 사용자 요청 또는 처리할 새 데이터
    실행 모습은? 오래 실행되는 학습 작업, 여러 가속기 사용 가능 서비스 요청마다 반복하거나 오프라인으로 일괄 처리
    주로 보는 값은? 손실, 평가 품질, 학습 시간·비용 품질, TTFT·E2EL, 처리량, 운영 비용
    대표 도구는? PyTorch, JAX, DeepSpeed, Megatron vLLM, SGLang, TensorRT-LLM, MAX, LMDeploy

    원문 비교표는 학습이 대체로 큰 초기 작업이고 추론이 트래픽에 따라 계속 드는 비용이라는 차이를 강조합니다. 그러나 어느 쪽의 누적 비용이 더 큰지는 제품마다 다릅니다. 사용자가 많은 서비스는 추론 비용이 학습 비용을 넘어설 수 있고, 규모가 큰 학습을 여러 번 반복하는 연구 프로젝트는 반대일 수 있습니다.

    모델의 전체 생애주기는 보통 데이터 준비 → 사전 학습 → 정렬·파인튜닝 → 평가 → 배포 → 추론·관측으로 이어집니다. 문제가 발견되면 평가와 학습으로 되돌아가 새 버전을 만드는 순환 과정입니다. 추론을 제공하는 서빙은 모델을 로드하고 API, 요청 대기열, 확장, 안정성을 관리하는 운영 단계입니다.

    자주 묻는 질문: 파인튜닝과 자체 학습은 어디에 속할까?¶

    파인튜닝은 학습인가요? 예. 기존 모델의 일부 또는 전체 가중치를 새 데이터로 조정하므로 학습입니다. 반면 프롬프트를 바꾸거나 검색 결과를 입력에 붙이는 일은 보통 가중치를 바꾸지 않으므로 추론 시점의 응용 방식입니다.

    모델 서빙은 무엇인가요? 학습된 모델을 애플리케이션이 쓸 수 있도록 패키징·로딩하고 API로 제공하며, 지연·안정성·보안·비용을 관리하는 일입니다. 추론은 그 안에서 모델이 수행하는 계산입니다.

    처음부터 자체 LLM을 학습해야 하나요? 원문은 대부분의 팀에 기존 모델에서 시작해 평가와 파인튜닝을 검토하라고 권합니다. 처음부터 학습하려면 방대한 데이터, 가속기, 연구·운영 인력이 필요합니다. 기존 모델로 요구 사항을 만족하지 못하거나 통제 요건이 특별한 경우에야 전체 학습을 검토할 근거가 생깁니다.

    추론 비용이 학습보다 더 클 수 있나요? 가능합니다. 개별 요청은 짧아도 수많은 사용자의 요청이 계속 쌓입니다. 다만 실제 총비용은 모델 개발 빈도, 트래픽, 응답 길이, 하드웨어와 운영 방식으로 계산해야 합니다.

    핵심 정리¶

    • 학습은 손실과 피드백으로 가중치를 바꾸고, 일반적인 추론은 가중치를 사용합니다.
    • 사전 학습뿐 아니라 파인튜닝도 학습입니다.
    • 추론은 실시간 API뿐 아니라 오프라인 일괄 처리에서도 일어납니다.
    • 학습의 초기 비용과 추론의 반복 비용 중 어느 쪽이 큰지는 사용량에 달려 있습니다.
    • 서빙은 추론 계산을 사용자에게 안정적으로 제공하는 운영 과정입니다.
