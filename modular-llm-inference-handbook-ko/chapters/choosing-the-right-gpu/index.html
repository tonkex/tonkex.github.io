    모델에 맞는 GPU는 어떻게 고를까?¶

    모델 파일이 24 GB라면 24 GB GPU 한 장으로 충분할까요? 실제 추론에는 가중치 외에 KV 캐시와 임시 메모리가 필요합니다. GPU 선택은 인기 제품의 순위를 외우는 일이 아니라 모델·요청 길이·동시성·응답 시간·예산을 함께 맞추는 과정입니다.

    이 장은 Modular의 GPU 선택 원문을 번역·재구성했습니다. 기준 원고는 커밋 07e93d6입니다. 보충 설명은 따로 표시했습니다.

    GPU, 그래픽 카드, 가속기는 어떻게 다른가?¶

    GPU는 많은 계산을 병렬로 수행하는 프로세서입니다. 그래픽 카드는 GPU 칩에 메모리, 전원·냉각 부품 등을 더한 하드웨어 제품을 가리킵니다. 클라우드에서는 카드 전체가 아니라 GPU가 포함된 인스턴스를 임대하는 경우가 많습니다. 가속기는 특정 계산을 빠르게 처리하도록 설계한 더 넓은 범주로, GPU 외에 TPU나 NPU도 포함합니다.

    따라서 클라우드 요금표의 ‘GPU 1개’가 어떤 칩, 메모리 용량, 서버 연결 방식을 뜻하는지 구체적인 인스턴스 사양을 확인해야 합니다. 같은 GPU 칩도 폼 팩터와 메모리·전력 한도에 따라 제품 사양이 달라질 수 있습니다.

    GPU 선택이 지연과 처리량을 바꾸는 이유는?¶

    모델의 가중치와 실행 중 생성되는 KV 캐시를 메모리에 담아야 추론을 시작할 수 있습니다. GPU의 메모리가 부족하면 여러 장에 모델을 나누거나, 정밀도를 낮추거나, 문맥 길이·동시 요청 수를 줄여야 합니다. 가중치가 들어간다고 해도 사용자에게 첫 답을 보내는 시간(TTFT)과 이어지는 토큰 생성 속도(TPOT)가 목표에 맞는지는 별도로 확인해야 합니다.

    원문은 대형 모델을 위한 데이터센터 GPU와 작은 모델에 적합한 중급 장비를 예로 듭니다. 특정 모델에 ‘이 GPU가 정답’이라는 관계는 시간이 지나면 바뀝니다. 모델의 양자화, 배치 크기, GPU 세대, 서빙 엔진이 함께 결과를 결정합니다.

    • Modular 원문: 추론 성능 지표 — TTFT·TPOT·처리량.

    소비자용·워크스테이션·데이터센터 GPU는 언제 쓸까?¶

    유형 유용한 상황 먼저 확인할 제약
    소비자용 로컬 실험, 작은 모델, 제한된 동시성 VRAM, 전력·냉각, 운영 지원
    워크스테이션 단일 장비의 개발·프로토타입 가격 대비 메모리와 확장성
    데이터센터용 많은 요청, 큰 모델, 다중 GPU 운영 대여·구매 비용, 공급 가능량, 네트워크

    원문은 RTX 4090·Radeon RX 7900 XTX, RTX A6000·Radeon Pro W6800, A100·H100·B200·MI300X 등을 각 범주의 예로 소개합니다. 이는 제품군을 이해하기 위한 예시이며, 현재 구매 가능성이나 특정 모델의 실측 성능을 보장하지 않습니다. 데이터센터 장비도 제품마다 메모리, 정밀도 지원, GPU 간 연결 방식이 다릅니다.

    어떤 사양을 어떤 순서로 볼까?¶

    첫째, VRAM 용량을 확인합니다. 가중치뿐 아니라 KV 캐시, 임시 활성값과 실행 여유분을 담아야 합니다. GPU 메모리 계산 장의 계산기로 1차 예산을 세우세요. 실제 모델의 가중치 형식과 서빙 엔진으로 로딩·부하 시험을 해야 최종 용량을 판단할 수 있습니다.

    둘째, 메모리 대역폭을 봅니다. 이는 GPU 메모리에서 연산 장치로 데이터를 옮기는 속도입니다. 요청 하나가 토큰을 하나씩 생성하는 decode 단계는 가중치 읽기의 영향이 큰 경우가 많습니다. 원문의 간단한 상한식은 다음과 같습니다.

    \[\text{단일 흐름의 이론적 토큰/초 상한} \approx \frac{\text{메모리 대역폭(바이트/초)}}{\text{토큰당 읽는 바이트}}\]

    예를 들어 70B 모델의 FP16 가중치가 약 140 GB이고 메모리 대역폭이 3.35 TB/s라면, 가중치만 읽는다고 가정한 값은 약 24 토큰/초입니다. 이는 실제 장비의 성능 예측치가 아닙니다. 가중치가 한 GPU에 다 들어가지 않을 수도 있고, KV 캐시·통신·커널·배칭이 결과를 바꿉니다. 여러 요청을 배치로 처리하면 같은 가중치 읽기를 나눠 쓸 수 있어 시스템 전체 처리량이 달라집니다.

    셋째, 연산 처리량과 정밀도 지원을 확인합니다. 긴 입력을 한꺼번에 처리하는 prefill은 행렬 연산의 영향이 큽니다. FLOPS 수치를 비교할 때는 같은 FP16·BF16·FP8 등 정밀도와 같은 희소성 조건인지 확인하세요. GPU가 어떤 형식을 저장할 수 있는지와 그 형식을 빠르게 계산하는 하드웨어가 있는지는 다른 문제입니다.

    한국어판 보충 설명: 사양표는 후보를 좁히는 도구입니다

    decode가 언제나 메모리 대역폭만으로 제한되고 prefill이 언제나 연산만으로 제한되는 것은 아닙니다. 작은 모델, 큰 배치, 긴 문맥, 커널 구현에 따라 병목이 이동합니다. 실제 입력·출력 길이와 동시 요청 수로 TTFT, TPOT, 처리량, 비용을 함께 측정하세요.

    여러 GPU를 연결하면 무엇이 달라질까?¶

    한 GPU에 모델이 들어가지 않으면 텐서 병렬화 같은 방법으로 가중치를 나눌 수 있습니다. 이때 GPU 사이에 중간 결과를 계속 주고받으므로 연결 속도가 중요합니다. 한 서버 안에서는 NVLink·NVSwitch·PCIe 같은 연결이, 여러 서버 사이에서는 네트워크가 영향을 줍니다. 메모리 총량이 두 배가 됐다고 응답 속도가 두 배가 되지는 않습니다.

    원문은 GPU 간 연결과 네트워크 토폴로지를 검토하라고 권합니다. GPU 유형만 고르지 말고 몇 장을 한 서버에 넣는지, 서로 어떻게 연결되는지, 노드 간 대역폭은 얼마인지 확인하세요. 작은 모델의 요청을 독립 GPU에 나누는 방식과 큰 모델 하나를 여러 GPU에 나누는 방식은 통신 비용이 다릅니다.

    비용·공급·소프트웨어 호환성은 어떻게 평가할까?¶

    원문은 장비 확보에서 통제력, 즉시 사용 가능성, 가격을 동시에 만족하기 어렵다는 경험칙을 소개합니다. 실제 조건은 공급자·계약 기간·지역·시점마다 달라집니다. 구매와 대여를 비교할 때는 GPU 시간당 가격뿐 아니라 가동률, 예약·대기 용량, 네트워크 비용, 운영 인력, 장애 대응을 포함하세요.

    소프트웨어 호환성도 필수입니다. NVIDIA 장비에는 드라이버·CUDA·서빙 엔진의 조합이, AMD 장비에는 ROCm과 엔진의 지원 범위가 중요합니다. 프레임워크가 원하는 GPU와 정밀도·커널을 지원하는지 공식 호환성 문서를 확인하세요. GPU 사양이 좋아도 필요한 연산이 지원되지 않으면 기대한 성능을 얻기 어렵습니다.

    • AMD: ROCm 지원 GPU — 제품·소프트웨어 지원 확인.

    모델과 GPU를 실제로 어떻게 맞춰 볼까?¶

    원문은 여러 공개 모델과 GPU를 대응시킨 표를 제공하지만, 표의 모델·하드웨어 구성은 시점에 따라 바뀝니다. 한국어판에서는 고정된 ‘추천 GPU’ 표 대신 다음 점검 순서를 사용합니다.

    1. 모델 카드에서 전체 가중치, 정밀도, 문맥 길이와 라이선스를 확인합니다. MoE라면 활성 매개변수만 보지 않습니다.
    2. 메모리 계산기에서 예상 요청 길이와 동시성을 넣어 후보 GPU 수를 좁힙니다.
    3. 선택한 서빙 엔진의 GPU·정밀도 지원을 확인하고 모델을 실제로 로드합니다.
    4. 실제 입력·출력 길이의 요청으로 TTFT, TPOT, 처리량, 오류율을 측정합니다.
    5. 같은 목표 품질과 지연을 만족하는 후보끼리 월간 총비용을 비교합니다.

    원문 FAQ처럼 모델 가중치는 보통 서비스 시작 시 저장소에서 읽어 CPU 메모리를 거쳐 GPU 메모리로 옮깁니다. 토큰을 생성할 때마다 디스크에서 가중치를 다시 읽는 것이 아닙니다. 다만 CPU 오프로딩 등 별도 전략을 쓰면 일부 데이터 이동이 일어날 수 있습니다.

    장비를 확인할 때 NVIDIA Linux 환경에서는 nvidia-smi, AMD에서는 amd-smi, macOS에서는 system_profiler SPDisplaysDataType을 사용할 수 있습니다. nvidia-smi의 CUDA Version은 설치된 Toolkit 버전이 아니라 드라이버가 지원하는 CUDA 버전의 상한 표시입니다. 실제 실행 가능 여부는 사용 중인 런타임·드라이버·컨테이너 구성과 호환성 문서로 판단하세요.

    핵심 정리¶

    • GPU의 VRAM은 가중치뿐 아니라 KV 캐시와 실행 여유분까지 담아야 합니다.
    • decode의 메모리 대역폭과 prefill의 연산 성능을 모두 살펴봅니다.
    • 여러 GPU를 쓰면 연결 속도와 통신 비용이 성능을 좌우할 수 있습니다.
    • 가격·공급과 프레임워크 호환성을 하드웨어 사양과 함께 확인합니다.
    • 최종 선택은 실제 모델과 요청으로 측정한 지연·처리량·총비용에 근거합니다.
