    어떤 LLM을 먼저 시험해야 할까?¶

    모델 목록에 Base, Instruct, Chat, MoE, Q4가 함께 보이면 무엇부터 골라야 할까요? 이름만 보고 가장 큰 모델을 선택하면 품질과 비용을 모두 잘못 예상할 수 있습니다. 이 장은 수행할 작업을 먼저 정하고, 모델 유형·접근 경로·파일 형식을 차례로 확인하는 방법을 설명합니다.

    이 장은 Modular의 모델 선택 원문을 번역·재구성했습니다. 기준 원고는 커밋 07e93d6입니다. 보충 설명은 따로 표시했습니다.

    기본 모델은 왜 바로 챗봇처럼 답하지 않을까?¶

    기본 모델(base model)은 대규모 자료에서 다음 토큰을 예측하도록 사전 학습한 모델입니다. 문장의 패턴과 일반 지식을 익히지만, 사용자의 명령을 안전하고 일관되게 따르도록 특별히 다듬어진 상태는 아닙니다. 예를 들어 “다음 문장을 요약해 줘”라는 요청 뒤에 요약 대신 비슷한 문장을 이어 쓸 수 있습니다.

    기본 모델을 출발점으로 명령 데이터에 추가 학습하면 지시형 모델을 만들 수 있습니다. 대화 데이터와 선호도 학습 등을 더해 대화에 맞춘 모델을 만들 수도 있습니다. 다만 실제 모델 제작 경로는 제품마다 다르므로 이름의 접미사만으로 학습 절차 전체를 알 수는 없습니다.

    관련 자료

    • Modular 원문: 기본 모델 — 사전 학습과 후속 조정.
    • Hugging Face: 모델 카드 — 모델의 용도와 제한을 확인하는 방법.

    지시형 모델과 채팅 모델은 어떻게 다를까?¶

    지시형 모델(instruction-tuned model)은 “이 문서를 요약해 줘”처럼 명령과 기대 답변의 예시로 조정한 모델입니다. 채팅 모델(chat model)은 대화 차례와 여러 화자의 문맥을 다루는 데 맞춰 추가 조정되거나, 그런 사용 방식을 목표로 배포됩니다. 원문은 이 차이를 설명하지만, 업계의 이름 사용은 일관되지 않습니다. 많은 지시형 모델도 채팅에 쓸 수 있습니다.

    실제로는 모델 카드에서 채팅 템플릿, 시스템 메시지 지원, 도구 호출 지원, 문맥 길이, 권장 추론 설정을 확인해야 합니다. 같은 가중치라도 템플릿을 잘못 적용하면 응답 품질이 떨어질 수 있습니다.

    한국어판 보충 설명: 용도에서 후보를 고르기

    짧은 분류·추출에는 작은 지시형 모델부터, 여러 차례 대화에는 대화 형식과 템플릿이 검증된 모델부터 시험하세요. 법률·의료·금융처럼 오류 비용이 큰 분야에서는 모델 이름보다 실제 사례에 대한 평가와 사람의 검토 절차가 중요합니다.

    관련 자료

    • Modular 원문: 지시형과 채팅 — 학습 목적의 차이.
    • Hugging Face Transformers: 채팅 템플릿 — 메시지를 모델 입력으로 바꾸는 형식.

    Dense와 MoE는 무엇을 다르게 계산할까?¶

    Dense 모델은 생성 단계에서 각 층의 매개변수를 사용합니다. MoE(Mixture of Experts) 모델은 일부 층에 여러 전문가 네트워크를 두고 토큰마다 그중 일부를 선택합니다. 따라서 MoE에서 “전체 매개변수 35B, 활성 매개변수 3B”처럼 두 숫자가 표시될 수 있습니다. 이는 전체 가중치가 3B 크기만큼만 저장된다는 뜻이 아닙니다. 선택되지 않은 전문가의 가중치도 배포 방식에 따라 메모리와 저장 공간을 차지합니다.

    구조 한 토큰의 계산 배포에서 확인할 점
    Dense 해당 층의 전체 가중치를 사용 모델 크기·정밀도·KV 캐시
    MoE 라우터가 선택한 전문가를 사용 전체 가중치 용량·전문가 배치·통신 비용

    원문은 MoE가 계산을 선택적으로 써서 확장 효율을 높일 수 있다고 설명합니다. 그러나 지연과 비용은 전문가의 수, 배치 크기, GPU 간 이동, 서빙 엔진 지원에 따라 달라집니다. 활성 매개변수 수만으로 GPU 크기를 결정하지 마세요.

    관련 자료

    • Modular 원문: Dense와 MoE — 두 구조의 비교.
    • Modular 원문: GPU 메모리 계산 — 가중치와 KV 캐시의 별도 예산.

    LLM 하나로 모든 작업을 처리해야 할까?¶

    원문은 작은 언어 모델, 임베딩 모델, 이미지 생성 모델, 비전 언어 모델, 음성 합성 모델을 함께 소개합니다. 임베딩 모델은 문서나 질문을 검색에 쓸 숫자 벡터로 바꿉니다. 비전 언어 모델은 이미지와 텍스트를 함께 처리합니다. 음성 합성 모델은 텍스트를 소리로 만듭니다. 이들 작업을 일반적인 텍스트 LLM 하나에 모두 맡길 필요는 없습니다.

    예를 들어 사내 문서 질의응답에서는 임베딩 모델로 관련 문서를 찾고, LLM은 찾은 문서를 바탕으로 답을 작성할 수 있습니다. 간단한 분류는 작은 모델로 처리하고 어려운 요청만 큰 모델로 보낼 수도 있습니다. 이렇게 여러 모델을 연결하면 각 단계의 품질, 지연, 오류 전파를 따로 평가해야 합니다.

    관련 자료

    • Modular 원문: 여러 모델 결합 — 작업별 모델 유형.
    • Modular 원문: 다중 모델 파이프라인 — 모델을 연결하는 운영 구조.

    모델은 어디에서 얻고 무엇을 확인할까?¶

    Hugging Face 모델 허브와 ModelScope는 모델 가중치와 모델 카드를 찾는 곳입니다. OpenRouter는 여러 모델을 API로 호출하는 접근 계층이며, 일반적으로 가중치를 내려받아 직접 운영하는 경로와 다릅니다. 먼저 가중치를 직접 실행할지 API로 평가할지 정하세요.

    공개된 모델이라고 모두 자유로운 상업 이용이 허용되는 것은 아닙니다. 모델 카드에서 라이선스, 사용 제한, 출처, 지원 언어, 권장 프롬프트 형식, 평가 방법, 문맥 길이를 확인하세요. 일부 모델은 로그인·약관 동의·접근 토큰이 필요합니다. 이를 게이트 모델이라고 합니다.

    한국어판 보충 설명: 재현 가능한 후보 목록

    평가 기록에는 모델 이름뿐 아니라 정확한 버전 또는 리비전, 가중치 형식, 토크나이저, 채팅 템플릿, 서빙 엔진 버전을 함께 적으세요. 같은 제품 이름의 새 릴리스가 나와도 이전 측정 결과를 재현할 수 있습니다.

    관련 자료

    • Hugging Face: 모델 카드 — 라이선스·용도·한계 기록.
    • Hugging Face: 게이트 모델 — 접근 승인 방식.

    가중치 파일 형식은 왜 중요한가?¶

    가중치는 학습으로 얻은 모델의 숫자 값이며, 배포할 때 파일에서 읽어 메모리에 적재합니다. 원문은 다음 형식을 소개합니다.

    형식 주로 쓰는 곳 확인할 점
    PyTorch 체크포인트 (.bin, .pt) 원래 학습 환경과 기존 배포 역직렬화 방식과 신뢰할 수 있는 파일인지 확인
    Safetensors (.safetensors) 공개 모델 배포와 서빙 샤드 파일과 model.safetensors.index.json의 완전성
    GGUF (.gguf) llama.cpp 계열의 로컬 실행 양자화 종류와 실행 도구의 호환성

    큰 모델의 Safetensors 파일은 여러 샤드(shard)로 나뉠 수 있습니다. 인덱스 파일은 각 텐서가 어느 샤드에 있는지 알려 줍니다. 파일 하나가 빠지면 모델 로드가 실패할 수 있습니다. GGUF 파일명에 들어간 Q4 같은 표시는 대체로 양자화 방식을 나타내지만, 형식 이름만으로 실제 품질이나 메모리를 확정할 수는 없습니다.

    한국어판 보충 설명: 파일 형식과 실행 안전성

    Safetensors는 텐서 데이터 로딩에서 임의 코드 실행을 피하도록 설계됐습니다. 그러나 모델 저장소에 있는 설정 파일이나 별도 사용자 코드까지 자동으로 안전하게 만드는 것은 아닙니다. 신뢰하지 않는 저장소의 실행 옵션은 별도로 검토하세요.

    • Hugging Face: Safetensors — 형식 설계와 로딩.
    • llama.cpp 공식 저장소 — GGUF 기반 로컬 실행.

    모델 이름과 평가 결과를 어떻게 읽을까?¶

    원문 도해는 이름의 숫자, B, Instruct, Chat, 양자화 표기와 릴리스 날짜를 해석합니다. B는 보통 십억 개의 매개변수를 뜻합니다. Instruct는 지시 조정을 암시하고 Q4는 대개 4비트 계열 양자화를 뜻하지만, 이름만으로 정확한 저장 형식과 지원 기능을 알 수 없습니다. MoE 이름에 35B-A3B처럼 두 수가 있다면 대개 전체·활성 매개변수 수를 나타냅니다. 전체 전문가 수와 활성 전문가 수를 뜻한다고 일반화하면 안 됩니다.

    선택 과정은 다음처럼 진행할 수 있습니다. ① 실제 사용 사례 20~50개를 모으고 ② 필요한 품질·지연·비용 상한을 정하고 ③ 작은 후보부터 같은 입력으로 평가하고 ④ 모델 카드·라이선스·서빙 호환성을 확인하고 ⑤ 최종 후보를 실제 트래픽 패턴으로 부하 시험합니다. 모델 순위표는 후보를 좁히는 자료이지 제품의 합격 판정이 아닙니다.

    핵심 정리¶

    • 기본 모델과 지시형·채팅 모델은 학습 목적과 입력 형식이 다릅니다.
    • MoE는 일부 전문가만 계산해도 전체 가중치의 메모리 요구를 고려해야 합니다.
    • 검색·시각·음성 등 작업에는 별도 전문 모델을 조합할 수 있습니다.
    • 모델 카드의 라이선스, 접근 조건, 템플릿과 파일 형식을 확인합니다.
    • 이름과 공개 순위보다 내 작업의 품질·지연·비용 측정이 중요합니다.
